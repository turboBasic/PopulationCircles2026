# ADR 0011 — A published answer is committed as the document that produced it

## Decision

Every answer this repository quotes is carried in the tree as the document the program printed, byte for
byte, under a top-level `results/` root. That root holds the answers the prose and the gallery point at and
nothing else — it is a corpus, not an archive of every run, and a document nobody points at does not belong
in it.

A committed document is produced by a maintainer's task that needs the raster, and is never hand-edited.
**Nothing compares it to a fresh run.** The only check it faces is that it still parses against the reader's
current schema. Where a run disagrees with a committed document, the answer is a regeneration with a date on
it: the new document replaces the old and the commit is the record of when the answer moved.

## Context

Every figure this project has published exists only as prose, and reproducing one takes a 7.5 GB raster and
the tables built from it. The documents themselves are small and are already exactly what the renderer reads
(ADR 0004), so carrying them makes a figure drawable from a clone that has fetched nothing, and gives the
wire format a regression corpus as a side effect.

What had to be settled is what happens when the program's answer moves. The obvious answer — a check that
recomputes and compares — is not available where the raster is fetched rather than carried (ADR 0009) and one
full-resolution search is about ninety minutes.

## Options

### Option 1 (SELECTED): committed documents, regenerated by hand, held only to the schema

- Adopted because: a quoted figure and a drawn figure gain one source, readable without the raster.
- Adopted because: a moved answer arrives as a diff in review, which is where someone would want to look at
  it.
- Adopted despite: nothing proves a committed answer is still what the program computes, so the corpus can
  go stale quietly between regenerations.
- Adopted despite: what the root holds is a judgment, and judgment drifts towards keeping every run.

### Option 2: a check that recomputes and compares

- Rejected because: it cannot run where the answer lives — no raster in CI, and ninety minutes if there
  were one.
- Rejected because: it would fail for a reason nobody can act on, since a deliberate improvement to the
  search and a regression read identically.
- Rejected despite: it is the only thing that would keep the corpus honest by itself.

### Option 3: publish nothing, and render from a run

- Rejected because: it puts every figure behind a fetch and an hour, which is exactly what nobody outside
  this clone can pay — a gallery built in CI could then not exist at all.
- Rejected despite: no committed answer can go stale if none is committed.

## Consequences

- **A stale answer in the tree is possible, and is the accepted cost.** What bounds it is that regenerating
  is one task and the result is a reviewable diff.
- ADR 0004 owns the format; this rules only that the tree carries instances of it. A schema bump therefore
  obliges regenerating the corpus in the same change, because the reader refuses a document above its
  version.
- A document no renderer can draw is still worth carrying as corpus. Which kinds render is the reader's
  business rather than this root's, so the root is not bounded by what can be drawn.
- Reopened if answers start moving often enough that regenerating and dating it stops being something anyone
  remembers to do.
